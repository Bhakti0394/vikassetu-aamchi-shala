  <files>src/routes/activities.$id.tsx</files>
  <read_first>src/routes/activities.$id.tsx</read_first>
  <action>
    Update `src/routes/activities.$id.tsx`:
    1. Child Selection:
       - Read initial `childId` from URL search param.
       - Allow teacher to select a child from a dropdown if none selected, or switch children.
    2. Step-Count Tracking:
       - Keep `done: number[]` step index state.
       - Calculate `completedSteps = done.length` and `totalSteps = a.steps.length`.
       - Do not mark steps complete automatically; strictly reflect teacher's step checklist.
    3. Outcome Buttons:
       - Render 3 buttons:
         - `"Tried — Helped"` (`tried_helped`)
         - `"Tried — Needs Support"` (`tried_needs_support`)
         - `"Not Tried"` (`not_tried`)
       - Add optional observation note input.
    4. Save & Offline Resilience:
       - Call `saveActivityLog({ childId, activityId: a.id, completedSteps, totalSteps, outcome, note })`.
       - If successful: show green confirmation badge (`"Saved trial: [Outcome]"`).
       - If failed (network/backend down): call `queuePendingTrial(...)` and show amber status:
         `"Saved to session queue (offline — will sync when backend reconnects)"`.
       - Clearly distinguish pending session trials from backend-confirmed records.
    5. Previous Trials History:
       - Query recent logs for this activity and selected child.
       - Display "Previous trials with [Child]:" showing date, outcome, and note if previously attempted.
  </action>
  <verify>Run `npm test` and `npm run build` to verify no regressions or build errors.</verify>
  <acceptance_criteria>
    - Teacher can select child, check steps, and log outcomes with one tap.
    - Strictly adheres to backend contract payload requirements.
    - Zero page crashes on network failure.
  </acceptance_criteria>
  <done>Activity Guide upgraded with outcome logging and offline session queueing.</done>
