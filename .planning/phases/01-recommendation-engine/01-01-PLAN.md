<task type="auto">
  <name>Task 1: Implement observation-based recommendation engine</name>
  <files>src/lib/recommend.ts</files>
  <read_first>src/lib/data.ts</read_first>
  <action>
    Create `src/lib/recommend.ts` with the exact specified API:
    1. Type definitions:
       - `ChildAnalysis`:
         - `childId: string`
         - `observedDomains: DomainId[]`
         - `latestScores: Record<DomainId, Score>`
         - `confidence: Record<DomainId, "early" | "high">` (early if baseline-only or count === 1)
         - `evidence: Record<DomainId, string[]>` (recent observation notes and activity names)
         - `weakestDomains: { domain: DomainId; score: Score; isEarly: boolean }[]`
         - `hasNoObservations: boolean`
       - `Recommendation`:
         - `child: Child`
         - `domain: DomainId`
         - `activity: Activity`
         - `level: Score`
         - `reason: string`
         - `evidence: string[]`
         - `isEarlySuggestion: boolean`
         - `secondaryActivity?: Activity`
         - `lastTrial?: { outcome: string; note?: string; date?: string }`
       - `ActivityLogSummary`: `{ childId: string; activityId: string; outcome: string; note?: string; createdAt?: string }`

    2. Function `observedDomainsOf(childId: string, observations: Observation[]): DomainId[]`:
       - Filter `observations` where `o.childId === childId`.
       - Return unique `domain` values preserving first-seen order.

    3. Function `analyseChild(child: Child, observations: Observation[]): ChildAnalysis`:
       - Filter observations for `child.id`, sorted newest-first by `date desc, id desc`.
       - Group by domain to determine latest score, whether the latest observation `is_baseline`, and collect notes for evidence.
       - Set `confidence[d] = "early"` if only baseline observations exist or observation count is 1; otherwise `"high"`.
       - Identify unobserved domains (domains with 0 observations).
       - Determine weakest domains: score 1 prioritized over score 2; tie-break by domain order.
       - Set `hasNoObservations = true` if child has zero observations across all 5 domains.

    4. Function `recommendFor(child: Child, observations: Observation[], logs?: ActivityLogSummary[]): Recommendation[]`:
       - Run `analyseChild(child, observations)`.
       - If `hasNoObservations`: return empty array (or early orientation suggestion), triggering "First observations pending" in UI.
       - For each weak domain (score < 3):
         - Find candidate activities from `ACTIVITIES` matching domain and `forLevel.includes(level)`.
         - Activity-Log Rotation: Check child's past logs. If an activity had `outcome === "tried_helped"`, deprioritize it and pick another activity in that domain first.
         - Find a `secondaryActivity` if available in the same domain.
         - Find `lastTrial` info from `logs` for the recommended activity if previously attempted.
         - Generate supportive, pedagogical rationale:
           - Growth mindset phrasing: *"Recommended because [Child] is practicing [Domain Name] (Level [Level]/3) and [Activity Name] develops [Skills]."*
           - Include evidence note if available from latest observation.
       - Return sorted recommendations (lowest score first, limit 2).

  </action>
  <verify>Verify that `src/lib/recommend.ts` compiles cleanly and exports `recommendFor`, `observedDomainsOf`, and `analyseChild`.</verify>

  </acceptance_criteria>
  <done>Core observation-driven recommendation engine is implemented.</done>
