  <files>src/lib/activityLogs.ts</files>
  <read_first>backend/app/schemas.py</read_first>
  <action>
    Create `src/lib/activityLogs.ts`:
    1. Define types matching backend schemas:
       ```ts
       export type ActivityLogOutcome = "tried_helped" | "tried_needs_support" | "not_tried";

       export type ActivityLogPayload = {
         childId: string;
         activityId: string;
         completedSteps: number;
         totalSteps: number;
         outcome: ActivityLogOutcome;
         note?: string;
       };

       export type ActivityLogRecord = ActivityLogPayload & {
         id: number;
         createdAt: string;
       };
       ```
    2. Export helper function `saveActivityLog(payload: ActivityLogPayload): Promise<{ success: boolean; data?: ActivityLogRecord; error?: string }>`:
       - Makes POST to `http://localhost:8000/api/activity-logs`.
       - Catches network errors or non-200 responses cleanly.
       - Returns `{ success: false, error: errorMessage }` on failure so caller can handle inline without throwing.
    3. Export helper function `fetchActivityLogs(childId?: string): Promise<{ success: boolean; data: ActivityLogRecord[]; error?: string }>`:
       - Makes GET to `http://localhost:8000/api/activity-logs${childId ? `?child_id=${childId}` : ""}`.
       - If backend is unreachable, returns `{ success: false, data: [], error: "Backend unreachable" }`.
    4. Ensure NO direct `localStorage` persistence is added (per requirement).

  </action>
  <verify>Check that `src/lib/activityLogs.ts` compiles and exports `saveActivityLog` and `fetchActivityLogs`.</verify>
  <acceptance_criteria>

    - No direct fetch logic needed in React components.
  </acceptance_criteria>
