  <files>src/components/ui-kit.tsx, src/routes/activities.$id.tsx, src/routes/children.$id.tsx</files>
  <read_first>src/components/ui-kit.tsx, src/routes/activities.$id.tsx, src/routes/children.$id.tsx</read_first>
  <action>
    1. In `src/components/ui-kit.tsx`, implement `SyncStatusBadge`:
       - Props: `{ pendingCount: number; failedCount: number; isSyncing: boolean; onSync: () => void }`
       - Visual States:
         - Idle (0 pending, 0 failed): Subtle, reassuring indicator `✓ Synced`.
         - Syncing: Amber/Teal pulsing badge with spinning icon: `Syncing {n} trial(s)...`.
         - Pending: Amber pill with item count and compact `"Sync now"` button.
         - Error / Failed: Coral/Amber warning pill with failed count, compact `"Retry"` button, and optional `"Clear failed"` prompt.
       - Accessibility:
         - Wrap state text in `<span role="status" aria-live="polite">` so screen readers announce sync completion without interrupting teacher actions.
         - Ensure color contrast meets WCAG AA standards (> 4.5:1).
    2. In `src/routes/activities.$id.tsx`:
       - Place `SyncStatusBadge` in the activity run header / session history section.
       - Allow single-click inline retry for any failed session trial.
       - Provide a simple `"Dismiss"` button on failed trials so corrupt test entries do not block the teacher's session.
    3. In `src/routes/children.$id.tsx`:
       - Replace temporary sync button in `Activity trials & progress` header with the standardized `SyncStatusBadge`.
       - When a trial is marked `sync_failed`, display the specific error inline (e.g. `"Network timeout"`) alongside an inline `"Retry"` button.
  </action>
  <verify>Run `npm test` and `npx tsc --noEmit` to confirm route compilation and test passing.</verify>
  <acceptance_criteria>
    - Sync status renders cleanly on desktop and mobile without layout shifts.
    - Inline retry re-attempts failed sync immediately.
    - Inline dismiss cleanly removes a rejected trial from storage.
    - Screen readers receive polite status announcements.
  </acceptance_criteria>
