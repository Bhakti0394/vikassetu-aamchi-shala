  <read_first>src/lib/activityLogs.ts, src/lib/activityLogs.test.ts</read_first>
  <action>
    Update `src/lib/activityLogs.ts`:
    1. Stable Client Trial Identifiers:
       - Update `QueuedActivityTrial` to include `clientTrialId: string` (generated via `crypto.randomUUID()` with fallback).
       - Ensure `clientTrialId` persists across retries and storage reloads so that a trial's identity never mutates.
    2. Client-Side Deduplication:
       - Maintain an in-flight set: `const inFlightSyncIds = new Set<string>()`.
       - Before issuing `saveActivityLog(payload)` for a trial, check if its `clientTrialId` is already in `inFlightSyncIds`. If so, skip it.
       - Discard identical submissions from UI within a short debouncing window (e.g. 500ms) for the same child + activity.
    3. Server-Side Idempotency Boundary Note:
       - Clearly document in code comments and architecture documentation that client-side deduplication guards against concurrent or accidental multi-clicks, but true end-to-end idempotency across network timeouts requires backend persistence of `client_trial_id`.
       - Prepare a non-breaking RFC for Bhakti proposing an optional `client_trial_id` in `ActivityLogCreate` for future backend implementation, without altering existing backend schemas today.
    4. Auto-Sync & Reconnection Listener:
       - Implement `registerAutoSyncListeners(onSyncComplete?: (result) => void): () => void`:
         - Subscribes to `window.addEventListener('online', ...)`.
         - Triggers `syncPendingTrials()` automatically when network returns.
         - Returns an unsubscribe cleanup function.
    5. Retry Backoff Strategy:
       - For items marked `sync_failed`, track `retryCount: number` and `nextRetryTime: number`.
       - Implement exponential backoff (e.g. 1s, 2s, 4s, 8s, max 30s) so failing servers are not hammered.
    6. Vitest test coverage:
       - Test deduplication prevents parallel sync calls for same trial ID.
       - Test `online` event triggers sync listener.
       - Test retry count increment and backoff delay calculation.
  </action>
